# Organization logo

Locator: `odd/tasks/organization-logo.md` (Engram mirror: `odd/organization-logo/tasks`).
Objective: make the organization profile's logo uploadable (FR-013, ADR-012 `logoAssetId`), show it on the profile page and on the review document letterhead (screen and print). Delivery `stacked-to-main`, three PRs, branches `organization-logo/<NN>-<slug>`; forecast about 1,100 authored lines, most of it tests. Test runners: Jest in `apps/api` (`npm test`, `npm run test:integration`, `npm run test:e2e`), Vitest in `apps/web` (`npm run test --workspace=@sf-manager/web`).

## Specs

- S1 (L1): "quiero que la gestora de fincas tenga un logo que se pueda subir". A user with `organizationProfile:update` uploads a logo; a new upload replaces the previous one.
- S2 (L2): accepted formats are PNG, JPEG and WebP ("si, es lo correcto"). The type is decided by the file's content (magic bytes), not by extension or declared content type. Maximum size about 2 MB. SVG is rejected and registered as an EN (sanitized SVG support).
- S3 (L3, option A, "si, adelante"): bytes live in a local Docker volume behind a hexagonal `FileStorage` port (`put`, `get`, `delete` by key, no paths or `fs` in the port). The stored key is opaque (`logos/<uuidv7>...`), never a filesystem path. The browser fetches the logo from the API (`GET /organization-profile/logo`), never from a static Caddy path. ADR-012 gets an addendum recording the local-volume decision and the open question "MinIO when review photos arrive".
- S4 (L4): `openspec/specs/organization-profile-management/spec.md` and `openspec/specs/organization-profile-admin-ui/spec.md` are edited in the same PR as the behavior ("si").
- S5 (L5): the logo appears in the review document letterhead, on screen and in print, in this change ("si"). `openspec/specs/review-document-ui/spec.md` (and `review-document` if the API response changes) is edited in that PR.
- S6 (assumption): removing a logo without replacing it is out of scope for this slice; registered as an EN.
- S7 (assumption): the logo volume is not covered by the TD-41 backup in this slice; registered as a TD with a pointer to EN-104.
- S8 (L13, "si"): roles that open a document see the logo only through that document: the letterhead gains `hasLogo`, and `GET /review-history/:sessionId/document/logo` is gated by `reviewSession:read` and the same scope check as the document read. `ROLE_PERMISSIONS` does not change. `authorization`, `review-document` and `review-document-ui` specs are edited.
