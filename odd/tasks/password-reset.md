# Password reset

Locator: `odd/tasks/password-reset.md` (Engram mirror: `odd/password-reset/tasks`).
Objective: self-service password reset by email (forgot password, emailed single-use link, new password), the first slice that sends email. Delivery `stacked-to-main`, four PRs (T2 split into T2a and T2b, L16), branches `password-reset/<NN>-<slug>`; forecast about 1,500 authored lines, most of it tests. Test runners: Jest in `apps/api` (`npm test`, `npm run test:integration`, `npm run test:e2e`), Vitest in `apps/web` (`npm run test --workspace=apps/web`).

## Specs

- S1 (L1, L3): "adelante con la recuperación de contraseña". A user without a session can ask for a reset link from the login page by entering their email, and set a new password from the emailed link.
- S2 (L4, L5): email goes out through Brevo over generic SMTP only: an `EmailSender` port with one SMTP adapter; message templates (subject and body, en/es/ca) live in the code; no Brevo REST API, stored templates or webhooks. Switching provider means changing `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` and DNS, with no code change. Sender `no-reply@bcnsynergy.com` (L7).
- S3 (assumption): the request endpoint always answers the same success response, whether or not the email belongs to an active user, so it cannot be used to find out which emails have accounts. Only an active (not soft-deleted) user gets an email. The response does not wait on the email being sent.
- S4 (assumption): the reset token is a random 256-bit value; only its SHA-256 hash is stored, with an expiry of 30 minutes. It is single use, and requesting a new one invalidates the user's earlier unused tokens. The link is `<public app URL>/reset-password#token=<token>`: the token travels in the fragment, so it never reaches a server log or a `Referer` header.
- S5 (assumption): setting the new password applies the existing password policy (`packages/validation/src/users/password.schema.ts`: at least 10 characters, one letter, one digit) and ends every session of that user (all refresh families revoked, so their access tokens stop working too, since the authenticated guard checks the session). An invalid, expired or used token answers one generic error.
- S6 (assumption): both endpoints are `@Public()` and rate-limited per client IP; the request endpoint also per email (HMAC key, as login). The email's language follows the language the user had selected in the web app (`en`, `es`, `ca`; default `en`).
- S7 (L8): link and open tracking must not apply to these emails: the link must reach the user pointing straight at the app. Checked on the first real email.
- S8 (assumption): web: a "Forgot your password?" link on the login page leads to a public page that asks for the email and then shows the same confirmation whatever the outcome; the reset page shows the password rules, asks for the new password twice, and on success sends the user to the login page with a notice; an invalid or expired link shows a message with a way to ask for a new one.
- S9 (L6): specs edited in the PR that changes the behavior: `openspec/specs/authentication/spec.md` (API flow), `openspec/specs/deployment/spec.md` (SMTP settings), a web spec for the two pages; a new ADR records the email decision; README, `prod.env.example` and `docker-compose.prod.yml` document the SMTP variables; a Mailpit service in the dev `docker-compose.yml` catches email locally.
